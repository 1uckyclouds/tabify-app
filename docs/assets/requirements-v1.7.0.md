## 1. 产品背景

### 1.1 整体目标
开发一个高效的Chrome浏览器标签页管理插件，帮助用户解决标签页过多导致的浏览器卡顿问题，提供一键收纳、智能分组、批量操作等功能，提升用户的浏览效率和体验。

### 1.2 目标用户群体
- **重度浏览器用户**：经常同时打开大量标签页的用户
- **知识工作者**：需要管理大量网页资源的研究人员、开发者、学生
- **效率追求者**：希望优化浏览器性能和工作流程的用户
- **OneTab用户**：希望从OneTab迁移或寻找更好替代方案的用户

### 1.3 核心价值主张
- **一键收纳**：快速释放浏览器内存，提升性能
- **智能分组**：AI驱动的自动分类，提高管理效率
- **无缝迁移**：完全兼容OneTab格式，零成本迁移
- **批量操作**：高效的批量管理功能

## 2. 核心操作流程

### 2.1 标签页收纳流程
```
用户打开多个标签页 → 点击插件图标 → 标签页被收纳并关闭 → 自动打开管理界面 → 显示收纳结果
```

### 2.2 标签页恢复流程
```
打开管理界面 → 浏览/搜索标签页 → 点击标签页项目 → 在新标签页中打开URL
```

### 2.3 批量操作流程
```
选择多个标签页 → 批量操作按钮变为可用状态 → 选择操作类型 → 执行批量操作 → 显示操作结果
```

### 2.4 智能分组流程
```
选择未分组标签页 → 点击智能分组 → AI分析内容并匹配现有分组 → 创建必要的新分组 → 标签页归类完成 → 可选择撤销操作
```

 5. 详细功能描述

### 5.1 一键收纳标签页

**功能概述**：提供快速收纳浏览器标签页的功能，释放内存并保存标签页信息。

**操作方式**：
- **左键点击插件图标**：直接收纳当前窗口所有标签页
- **右键点击插件图标**：显示收纳选项菜单

**右键菜单选项**：
- 收纳当前标签页 [显示当前URL]
- 收纳左侧标签页 (显示数量)
- 收纳右侧标签页 (显示数量)  
- 收纳除当前页面以外所有标签页 (显示数量)
- 收纳所有窗口标签页 (显示数量)
- 打开管理界面

**收纳逻辑**：
- 当前标签页：仅收纳当前活动标签页
- 左侧标签页：当前标签页左边的所有标签页
- 右侧标签页：当前标签页右边的所有标签页
- 其他标签页：除当前标签页外的所有标签页
- 所有窗口：浏览器中所有窗口的全部标签页

### 5.2 标签页列表管理

**功能概述**：提供已收纳标签页的查看、搜索和基本管理功能。

**界面元素**：
- 搜索框：实时过滤标签页
- 标签页项目：显示标题/URL、图标
- 复选框：支持多选操作
- 虚拟滚动：优化长列表性能

**标签页项目显示逻辑**：
- **优先显示标题**：如果成功获取到标签页标题，则显示标题作为主要文本
- **降级显示URL**：如果标题加载失败或为空，则直接显示URL作为主要文本
- **悬停显示完整信息**：鼠标悬停时显示完整的标题和URL信息

**Favicon显示逻辑**：
- **优先显示真实favicon**：如果成功获取到网站的favicon，则显示真实图标
- **降级显示默认图标**：如果favicon获取失败或为空，则显示统一的默认占位符图标
- **图标尺寸**：统一显示为16x16像素，保持界面整齐
- **加载状态**：favicon加载过程中显示加载占位符，避免界面闪烁

**交互行为**：
- 点击标签页标题/URL：在新标签页中打开URL
- 勾选复选框：选择标签页进行批量操作
- 拖拽标签页：移动到其他分组

#### 5.2.1 Favicon处理详细方案

**获取方式**：
1. **Chrome Tabs API**：优先使用`chrome.tabs.query()`获取的`tab.favIconUrl`
2. **标准favicon路径**：如果API未提供，尝试访问`${domain}/favicon.ico`
3. **HTML解析**：解析页面`<link rel="icon">`标签获取自定义图标路径
4. **缓存机制**：成功获取的favicon缓存到本地存储，避免重复请求

**存储格式**：
- **URL格式**：优先存储favicon的URL地址
- **Base64格式**：对于小尺寸图标（<10KB），转换为base64存储以提高加载速度
- **过期机制**：favicon缓存7天后过期，重新获取

**显示降级方案**：
1. **真实favicon**：显示网站的实际图标
2. **域名默认图标**：根据域名生成的默认图标（如Google的"G"）
3. **通用占位符**：统一的地球图标🌐作为最终降级方案

**错误处理**：
- **网络错误**：favicon请求失败时，立即使用默认图标，不阻塞界面渲染
- **格式错误**：非图片格式的favicon自动降级到默认图标
- **尺寸异常**：过大的favicon自动缩放到16x16像素

**性能优化**：
- **懒加载**：只有可见区域的favicon才进行加载
- **批量请求**：合并多个favicon请求，减少网络开销
- **内存管理**：限制favicon缓存大小，超出限制时清理最久未使用的图标

### 5.3 批量操作和恢复

**功能概述**：支持对多个标签页进行批量操作，提高管理效率。

**界面设计**：
- **固定工具栏**：操作按钮始终显示在固定位置，避免界面跳动
- **状态控制**：未选中标签页时，批量操作按钮置灰不可点击
- **选择反馈**：底部状态栏显示当前选中的标签页数量

**选择方式**：
- **页面级全选**：选中所有可见的标签页（包括已分组和未分组）
- **分组级全选**：选中指定分组下的所有标签页
- **单项多选**：通过复选框选择多个标签页

**批量操作按钮状态**：
- **可用状态**：选中一个或多个标签页时，按钮变为可点击状态
- **置灰状态**：未选中任何标签页时，按钮置灰并显示悬停提示
- **智能分组特殊状态**：只有选中未分组标签页时才可用，选中已分组标签页时显示提示

**批量操作功能**：
- 批量恢复：在新标签页中打开所有选中URL
- 批量删除：删除所有选中的标签页记录
- 添加到分组：将选中标签页添加到指定分组
- 智能分组：对选中的未分组标签页进行AI分组

### 5.4 数据导入导出

**功能概述**：支持数据的备份、恢复和跨设备同步，兼容OneTab格式。

**支持格式**：
- JSON格式：完整的数据结构，包含分组信息和favicon数据
- OneTab格式：纯文本"URL | 标题"格式，兼容OneTab

**导入功能**：
- 文件格式自动识别
- 数据冲突处理（覆盖/合并/跳过）
- OneTab迁移向导
- Favicon重新获取：导入后自动获取缺失的favicon

**导出功能**：
- 多格式选择
- 自动下载到下载文件夹
- 错误处理和用户提示
- Favicon数据包含：JSON格式导出包含favicon信息

## 5.5 标签页分组和标记

**功能概述**：提供多种分组方式和标记功能，帮助用户组织管理标签页。

**分组类型**：
- 手动分组：用户自定义名称和颜色
- 域名分组：按URL域名自动分组
- AI智能分组：基于内容分析的自动分类（详见5.5.1节）

**分组显示信息**：
- 分组名称和颜色
- 包含的标签页数量
- 分组创建时间（显示为相对时间，如"2小时前"、"昨天"、"2024-01-15"）
- 锁定状态指示

**分组操作**：
- **分组重命名**：单击分组名称进入编辑模式，单击编辑框外区域保存
- **分组锁定/解锁**：点击锁定按钮切换分组锁定状态，锁定后AI不会向其添加新标签页
- **分组删除**：删除前弹出确认对话框，用户可选择是否保留组内标签页
  - 保留：标签页全部移入"未分组"
  - 不保留：同时删除分组和组内所有标签页
- 展开/折叠分组
- 拖拽调整分组
- 分享分组

#### 5.5.1 AI智能分组详细实现方案

**功能概述**：通过大语言模型分析未分组标签页的标题和URL，智能匹配现有分组或创建新分组。

**作用范围限制**：
- **仅作用于未分组标签页**：智能分组只处理"未分组"状态的标签页
- **保护已有分组**：已分组的标签页不会被重新分类，保持用户的手动分组结构
- **尊重锁定分组**：锁定状态的分组不会接收AI分配的新标签页

**分析数据源**：
- **主要数据**：标签页标题（title）
- **辅助数据**：URL域名和路径
- **可选数据**：页面描述（如果可获取）

**智能分组策略**：
1. **现有分组匹配优先**：
   - AI首先分析现有分组的名称和内容特征
   - 将待分组标签页与现有分组进行匹配
   - 优先分配到最匹配的现有分组（排除锁定分组）

2. **新分组创建规则**：
   - 当标签页无法匹配现有分组时，AI创建新分组
   - 根据剩余未匹配标签页数量限制新分组数量：
     - 1-5个标签页：最多创建1个新分组
     - 6-15个标签页：最多创建2-3个新分组
     - 16-30个标签页：最多创建3-5个新分组
     - 30+个标签页：最多创建5-8个新分组

3. **无现有分组时的自适应分组**：
   - 当不存在任何已有分组时（"未分组"不算已有分组）
   - AI根据选中标签页数量自适应创建合适数量的分组
   - 分组数量计算：Math.ceil(标签页数量 / 8)，最少2个，最多8个

**AI提示词模板**：
```
请分析以下未分组的网页标签页，将它们智能分配到合适的分组中：

现有分组（排除锁定分组）：
- "前端开发" (包含React、Vue相关内容)
- "学习资料" (包含教程和文档)
- "工作项目" (包含项目管理和协作工具)

待分析标签页：
1. 标题："{title1}" URL："{url1}"
2. 标题："{title2}" URL："{url2}"
...

分组规则：
1. 优先匹配现有分组
2. 无法匹配时创建新分组，但新分组数量不超过{maxNewGroups}个
3. 确保每个分组至少包含2个标签页

请返回JSON格式的分组结果：
{
  "assignments": [
    {
      "tab_id": 1,
      "group_type": "existing",
      "group_name": "前端开发",
      "confidence": 0.9
    },
    {
      "tab_id": 2,
      "group_type": "new",
      "group_name": "设计资源",
      "confidence": 0.8
    }
  ]
}
```

**撤销功能**：
- **操作前备份**：执行智能分组前自动保存当前分组状态
- **撤销通知**：分组完成后显示"已创建3个智能分组 [撤销] [保留]"通知（30秒内有效）
- **完整恢复**：撤销时恢复到分组前的完整状态，包括分组结构和标签页分配

**技术实现方案**：

1. **AI服务集成选项**：
   - **OpenAI GPT API**：使用GPT-3.5/GPT-4进行内容分析
   - **本地模型**：集成轻量级本地模型（如Ollama）
   - **其他API**：支持Claude、Gemini等其他AI服务

2. **数据处理流程**：
   ```javascript
   // 伪代码示例
   async function intelligentGrouping(tabs) {
     // 1. 数据预处理
     const processedTabs = tabs.map(tab => ({
       id: tab.id,
       title: cleanTitle(tab.title),
       domain: extractDomain(tab.url),
       path: extractPath(tab.url)
     }));
     
     // 2. 批量分析（避免频繁API调用）
     const batchSize = 20; // 每次分析20个标签页
     const results = [];
     
     for (let i = 0; i < processedTabs.length; i += batchSize) {
       const batch = processedTabs.slice(i, i + batchSize);
       const analysis = await callAIService(batch);
       results.push(...analysis.groups);
     }
     
     // 3. 结果处理和分组创建
     return createGroupsFromAnalysis(results);
   }
   ```

3. **错误处理和降级方案**：
   - **网络错误**：显示错误提示，提供重试选项
   - **API限制**：实现请求队列和频率限制
   - **分析失败**：降级到域名分组或手动分组
   - **部分失败**：对成功分析的部分进行分组，失败的保持原状

**用户交互流程**：

1. **触发分组**：
   - 用户选择多个未分组标签页
   - 点击"智能分组"按钮
   - 系统检查AI功能是否启用和配置

2. **分析过程**：
   - 显示进度对话框："正在分析标签页内容..."
   - 实时更新进度："已分析 15/50 个标签页"
   - 显示预估剩余时间

3. **结果预览**：
   - 显示分组建议对话框
   - 区分显示：
     - 🆕 新创建的分组
     - 📁 匹配到的现有分组
   - 列出建议的分组和包含的标签页
   - 用户可以：
     - 接受所有建议
     - 修改分组名称
     - 调整标签页分配
     - 取消操作

4. **执行分组**：
   - 创建新的分组

## 7. 验收标准

### 7.1 一键收纳标签页
1. 当用户左键点击插件图标时，系统应直接收纳当前窗口所有标签页并关闭它们，无需二次确认
2. 当收纳完成后，系统应自动打开插件主页，展示已收纳的标签页列表
3. 当标签页被收纳时，系统应保存标签页的标题、URL、图标信息
4. 当用户右键点击插件图标时，系统应显示上下文菜单，包含所有收纳选项
5. 当用户通过右键菜单选择收纳操作时，系统应直接执行对应的收纳功能，无需二次确认
6. 当收纳完成时，系统应显示收纳的标签页数量

### 7.2 标签页列表管理
1. 当用户打开插件主界面时，系统应显示所有已收纳的标签页列表
2. 当用户在搜索框中输入关键词时，系统应实时过滤显示匹配标题或URL的标签页
3. 当用户点击标签页项目时，系统应在新标签页中打开该URL
4. 当用户查看标签页列表时，每个标签页项目前应显示复选框，用户可通过复选框选择多个标签页
5. 当标签页列表很长时，系统应提供虚拟滚动以提升性能
6. 当标签页项目有有效标题时，系统应优先显示标题而不显示URL
7. 当标签页项目标题加载失败或为空时，系统应直接显示URL作为主要文本
8. 当用户鼠标悬停在标签页项目上时，系统应显示完整的标题和URL信息
9. 当显示标签页项目时，系统不应显示单个标签页的时间戳信息
10. **当标签页收纳时，系统应尝试获取并保存网站的favicon**
11. **当favicon成功获取时，系统应在标签页项目中显示真实的网站图标**
12. **当favicon获取失败时，系统应显示统一的默认占位符图标（地球图标🌐）**
13. **当favicon正在加载时，系统应显示加载占位符，避免界面闪烁**
14. **当显示favicon时，系统应统一缩放到16x16像素，保持界面整齐**
15. **当favicon缓存过期时，系统应自动重新获取最新的网站图标**

### 7.3 批量操作和恢复
1. 当用户通过复选框选择标签页时，系统应允许多选标签页
2. 当用户未选中任何标签页时，系统应将批量操作按钮（恢复、删除、添加到分组、智能分组）置为灰色不可点击状态
3. 当用户选中一个或多个标签页时，系统应将批量操作按钮变为可用状态
4. 当用户鼠标悬停在置灰的批量操作按钮上时，系统应显示"请先选择标签页"的提示信息
5. **当用户点击"全选所有"时，系统应选中所有可见的标签页（包括已分组和未分组）**
6. **当用户点击分组的"全选本组"时，系统应只选中该分组下的所有标签页**
7. 当用户点击"批量恢复"时，系统应在新标签页中打开所有选中的URL
8. 当用户点击"批量删除"时，系统应从列表中移除所有选中的标签页
9. 当用户选中标签页时，系统应在底部状态栏显示"已选择 X 项"的计数信息
10. 操作工具栏应始终固定显示，避免因选择状态变化造成的界面跳动

### 7.4 数据导入导出
1. 当用户点击"导出数据"时，系统应支持两种格式导出（JSON格式、OneTab兼容的"URL | 标题"纯文本格式）
2. 当用户选择导入文件时，系统应支持解析两种格式（JSON格式、OneTab的"URL | 标题"纯文本格式）
3. 当导入OneTab格式数据时，系统应正确解析"URL | 标题"格式的文本文件，每行一个标签页
4. 当导入数据与现有数据冲突时，系统应提供选项（覆盖、合并、跳过）
5. 当导出完成时，系统应自动下载文件到用户的下载文件夹
6. 当导入格式错误时，系统应显示错误信息并不影响现有数据
7. 当用户从OneTab迁移时，系统应提供专门的迁移向导帮助用户导入数据
8. **当导出JSON格式时，系统应包含favicon数据，确保导入后图标正常显示**
9. **当导入数据后，系统应自动获取缺失的favicon，补充图标信息**

### 7.5 标签页分组和标记
1. 当标签页被收纳时，系统应默认将其放入"未分组"状态，并记录分组创建时间
2. 当用户选择多个标签页后，系统应在操作工具栏中提供"添加到分组"选项
3. 当用户创建新分组时，系统应允许用户输入分组名称和选择颜色
4. 当用户查看分组时，系统应在分组标题栏显示分组创建时间（格式为相对时间或绝对时间）
5. 当用户查看分组时，系统应以可收起/展开的行形式显示分组，点击分组名可展开/收起显示该分组的标签页
6. **当用户单击分组名称时，系统应进入编辑模式，显示文本输入框**
7. **当用户在分组名称编辑状态下单击编辑框外区域时，系统应保存新的分组名称并退出编辑模式**
8. **当用户点击分组锁定按钮时，系统应切换分组的锁定状态，锁定后显示🔒图标，解锁后显示🔓图标**
9. **当分组处于锁定状态时，AI智能分组不应向该分组添加新的标签页**
10. **当用户点击分组删除按钮时，系统应弹出确认对话框，提供两个选项：**
    - **"保留标签页，移入未分组"**
    - **"同时删除分组和所有标签页"**
11. **当用户选择"保留标签页"选项删除分组时，系统应将组内所有标签页移入"未分组"状态**
12. **当用户选择"同时删除"选项时，系统应删除分组及其包含的所有标签页**
13. **当用户选择"按域名分组"时，系统应只对选中的未分组标签页根据URL域名进行自动分组（如google.com、github.com等）**
14. **当用户选择"智能分组"时，系统应只对选中的未分组标签页进行AI分析和分组**
15. **当用户选中的标签页包含已分组项目时，智能分组按钮应显示提示"请选择未分组的标签页"**
16. **当AI智能分组完成时，系统应显示撤销通知，用户可在30秒内撤销分组操作**
17. **当用户点击撤销时，系统应完全恢复到智能分组前的状态**
18. **当不存在任何已有分组时，AI应根据选中标签页数量自适应创建合适数量的分组**
19. **当存在已有分组时，AI应优先将标签页匹配到现有分组，无法匹配时才创建新分组**
20. **当AI创建新分组时，新分组数量应根据剩余标签页数量进行限制**
21. 当用户点击"解除分组"时，系统应一键将所有标签页恢复到未分组状态，并更新分组创建时间
22. 当用户选择多个标签页时，系统应支持批量添加到同一分组或进行智能分组
23. 当用户拖拽标签页项目时，系统应允许将标签页拖放到其他分组中，实现快速分组调整
24. 当用户选择多个标签页后拖拽时，系统应支持批量拖拽到目标分组

### 7.6 用户体验优化
1. 当没有收纳任何标签页时，系统应显示空状态提示和操作引导
2. 当用户执行删除操作时，系统应显示确认对话框，特别是批量删除操作
3. 当系统执行耗时操作时，系统应显示加载状态指示器
4. 当操作完成时，系统应显示成功或失败的通知提示
5. 当标签页数量很多时，系统应提供分页或懒加载以提升性能
6. 当用户点击分组操作按钮时，系统应提供"分享分组"选项，生成分享链接或二维码
7. 当用户选择分享功能时，系统应支持将标签页集合导出为可分享的格式

### 7.7 设置和个性化
1. 当用户打开设置页面时，系统应显示所有可配置选项，包括外观、行为、快捷键、AI功能、数据管理等设置
2. 当用户修改主题设置时，系统应立即应用新的颜色主题（浅色/深色/跟随系统/像素模式）
3. 当用户选择像素模式时，系统应应用复古像素风格的界面样式，包括像素字体和8位色彩风格
4. 当用户设置自动收纳规则时，系统应在达到指定标签页数量时自动收纳
5. 当用户查看快捷键设置时，系统应显示当前的快捷键配置，并提供跳转到Chrome扩展管理页面的链接以便用户修改快捷键
6. 当用户启用/禁用AI功能时，系统应相应显示或隐藏智能分组相关选项
7. 当用户设置数据清理选项时，系统应按照设定的时间自动清理过期数据
8. 当用户更改设置时，系统应自动保存配置并在重启浏览器后保持设置

## 8. 技术约束

### 8.1 平台要求
- Chrome浏览器扩展 (Manifest V3)
- 支持Chrome 88+版本
- 需要网络权限（用于AI功能和favicon获取）
- 需要存储权限（本地数据存储）
- 需要标签页权限（标签页管理）

### 8.2 性能要求
- 标签页收纳响应时间 < 1秒
- 列表渲染支持1000+标签页流畅滚动
- 搜索响应时间 < 300ms
- 分组名称编辑响应时间 < 200ms
- AI智能分组响应时间 < 30秒
- Favicon获取超时时间 < 5秒

### 8.3 兼容性要求
- 完全兼容OneTab导出格式
- 支持跨设备数据同步（通过导入导出）
- 向后兼容数据格式
- 支持各种favicon格式（ico、png、svg等）

### 8.4 技术限制
- 快捷键只能在manifest.json中预定义，用户需通过Chrome设置页面修改
- AI功能需要网络连接，受内容安全策略限制
- 无法访问其他扩展的数据，需用户手动导入
- 存储空间受Chrome扩展存储配额限制
- Favicon获取受同源策略限制，部分网站可能无法获取

### 8.5 AI功能技术要求
- **网络权限**：需要在manifest.json中声明外部AI服务域名
- **API调用限制**：需要实现请求频率限制和错误重试机制
- **数据安全**：API密钥需要加密存储，敏感数据需要过滤
- **性能要求**：单次AI分析响应时间应 < 30秒，支持批量处理
- **降级方案**：AI服务不可用时需要提供备选分组方案
- **缓存机制**：需要实现分析结果缓存，避免重复分析相同内容

### 8.6 Favicon处理技术要求
- **获取权限**：需要网络权限访问外部favicon资源
- **存储限制**：favicon缓存大小限制在50MB以内
- **格式支持**：支持ico、png、jpg、svg等常见图标格式
- **性能优化**：实现favicon懒加载和批量获取机制
